Q-1

Three Main Functional Components of the CPU & Four Types of Memory

Infographic: CPU Architecture & Memory Hierarchy

A. Three Main Functional Components of the CPU

1. Control Unit (CU)

Acts as the supervisor of the computer. It fetches instructions from memory, decodes what needs to be done, and sends timing and control signals to coordinate the ALU, memory, and I/O devices.

2. Arithmetic Logic Unit (ALU)

The computational engine of the CPU. It carries out mathematical calculations (addition, subtraction, multiplication) and logical decision-making operations (AND, OR, NOT, greater-than/equal comparisons).

3. Registers

High-speed temporary storage locations built directly inside the processor chip. They hold active instructions, memory addresses, and intermediate calculation results during execution.

B. Four Types of Main / Primary Memory & Key Characteristics

1. Registers

Key Characteristic: Fastest memory in the computer (operates at CPU clock speed), directly inside the CPU, with tiny capacity (a few bytes).

2. Cache Memory

Key Characteristic: Ultra-fast SRAM placed between the CPU and RAM that stores frequently used instructions/data to prevent CPU waiting delays.

3. RAM (Random Access Memory)

Key Characteristic: Volatile read/write working memory that holds active programs and data; contents are erased immediately when power is turned off.

4. ROM (Read-Only Memory)

Key Characteristic: Non-volatile memory that permanently stores essential firmware (like BIOS/UEFI) needed to start up the computer.

Q-2

The Fetch–Decode–Execute Instruction Cycle & Register Interactions

Infographic: Step-by-Step Register & Bus Flow

Every program instruction is processed through a continuous loop called the Fetch–Decode–Execute cycle (machine cycle). Key registers and functional units coordinate over the system buses (Address, Data, and Control buses):

  • 1. Fetch Phase: The Program Counter (PC) holds the memory address of the next instruction. This address is copied into the Memory Address Register (MAR) and placed on the Address Bus. The Control Unit (CU) sends a Memory Read signal to Main Memory (RAM). RAM places the instruction onto the Data Bus, where it is received by the Memory Data Register (MDR) and transferred into the Instruction Register (IR). Simultaneously, the PC is incremented (PC ← PC + 1) so it points to the subsequent instruction.
  • 2. Decode Phase: The Control Unit (CU) inspects the binary instruction inside the IR, splitting it into an opcode (what action to perform, e.g., ADD or LOAD) and an operand (the memory address of the required data). If data must be retrieved from RAM, the operand's address is sent to the MAR, and RAM loads that data value into the MDR.
  • 3. Execute Phase: The CU issues control signals to carry out the instruction. For arithmetic or logic instructions, the ALU takes the data from the MDR and combines it with the value currently held in the Accumulator (ACC), storing the newly computed result back into the ACC. If the instruction is a STORE command, the value in the ACC is transferred to the MDR and written back to Main Memory at the address held in the MAR. The cycle then restarts for the next instruction.
Q-3

Deploying Magnetic Disks (HDDs) & Magnetic Tape in a University Computer Centre

Infographic: Two-Tier University Student Record Storage Architecture

1. Live Student Records on Magnetic Disks (HDD Arrays)

  • Why HDDs: Student portals, fee counters, and exam offices perform thousands of random read/write queries every minute (e.g., looking up Roll No. 2045). Magnetic disks support direct (random) access with seek times in milliseconds.
  • Deployment Setup: Enterprise SAS/SATA hard drives are configured in a RAID array (such as RAID-10 or RAID-5) inside the university database server so that if a single disk fails, live records stay online without interruption.

2. Periodic Backups on Magnetic Tape (LTO Cartridges)

  • Why Magnetic Tape: Backing up the entire student database does not require random searches—data is written sequentially in one continuous stream, where modern LTO tapes achieve high sustained transfer speeds at the lowest cost per terabyte.
  • Deployment & Rotation (GFS Scheme): Automated backup software runs daily incremental backups and weekly/monthly full backups to an automated tape library. Cartridges are physically ejected (creating an air gap safe from hackers/ransomware) and stored in an off-site vault for disaster recovery.

Sequential Access Devices vs. Direct Access Devices

Infographic: How Data Is Located & Retrieved

Sequential Access (Magnetic Tape)

Must wind through Block 1 → Block 2 → Block 3 to reach Block 4.

B1 → B2 → B3 → TARGET (B4)

Access latency depends on physical tape position (seconds to minutes).

Direct / Random Access (HDD, Optical Disc)

Read/write head or laser jumps straight to the target track & sector.

HEAD ⟶ Jumps Directly ⟶ TARGET (Track 14, Sector 8)

Near-uniform access time regardless of file location (milliseconds).

Comparison Parameter Sequential Access Devices (e.g., Magnetic Tape) Direct Access Devices (e.g., Magnetic Disk, Optical Disc)
Data Retrieval Method Linear/sequential traversal: data must be read or skipped in exact physical order from the start of the tape until the target record is reached. Addressable coordinates: each track and sector has a unique physical address, allowing the read/write head or laser to jump directly to the desired block.
Access Time Very Slow (Seconds to Minutes): Winding/rewinding reels to locate a specific file causes high latency, though sequential streaming speed is high. Fast (Milliseconds): Magnetic HDDs take ~4–12 ms; optical drives take ~80–150 ms regardless of where the file sits on the platter/disc.
Typical Applications Automated nightly server backups, cold archival storage, disaster recovery vaults, and batch processing of massive sequential logs. Operating systems, live transactional databases, everyday file storage (HDDs), software distribution, and media playback (CD/DVD/Blu-ray).
Cost per Unit of Storage Lowest (~$0.005–$0.01 per GB): Cartridges are inexpensive plastic reels; the expensive mechanism resides in the single tape drive. Low to Moderate (~$0.015–$0.03 per GB for HDD; ~$0.03–$0.06 per GB for Blu-ray): Higher precision mechanics per drive/disc increase cost over tape.

Comparison of RAM (SRAM, DRAM) vs. ROM (PROM, EPROM, EEPROM)

Infographic: Boot-Up vs. Runtime Role

Phase 1: Power-On & System Boot-Up → ROM

When you press the power button, RAM is completely empty. The CPU automatically jumps to ROM (EEPROM / Flash BIOS-UEFI) to run the Power-On Self-Test (POST), initialize hardware, and load the Operating System bootloader into RAM.

Phase 2: Program Execution → DRAM & SRAM

Once booted, the OS and user apps reside in DRAM (Main Memory) for large working capacity, while active instructions and variables are cached in SRAM (L1/L2/L3 Cache) so the CPU executes them at maximum speed.

Assessment of Archival Media for Long-Term Institutional Records

Infographic: Multi-Criteria Archival Media Scorecard

1. Magnetic Tape Library (WINNER)

Capacity: Up to 18 TB native (45 TB compressed) per cartridge; petabytes in libraries

Cost Efficiency ($/GB): ~$0.005–$0.01/GB (Best)

Durability: 15–30 years in climate control

Retrieval Time: Seconds to minutes (Robotic mount + seek)

2. HDD Mass Storage Array (RAID/NAS)

Capacity: 16–24 TB per drive; scalable to petabytes

Cost Efficiency ($/GB): Moderate + high 24/7 electricity/cooling

Durability: 3–5 years motor/bearing lifespan

Retrieval Time: Instant (Milliseconds) — best for active data

3. Optical Discs (CD/DVD/Blu-ray)

Capacity: Very Low (700 MB CD, 4.7 GB DVD, 25–100 GB Blu-ray)

Cost Efficiency ($/GB): High labor & media overhead at TB scale

Durability: 20–50+ years (M-DISC/archival grade)

Retrieval Time: Milliseconds if mounted; hours if manual shelf swap

Final Verdict & Justification: A Magnetic Tape Library (LTO-8 / LTO-9) is the most suitable medium for long-term archiving of institutional records.

  • Storage Capacity: A single LTO-9 cartridge stores 18 TB natively (up to 45 TB compressed), and automated robotic libraries scale effortlessly to multi-petabyte institutional archives—whereas optical discs would require tens of thousands of individual discs.
  • Cost per GB: Tape delivers the lowest total cost of ownership (~$0.005–$0.01/GB) and consumes zero electricity once written and shelved, unlike RAID/NAS disk arrays that require continuous power, cooling, and drive replacements every 3–5 years.
  • Durability & Security: Properly stored LTO tape lasts 15–30 years, resists bit-rot better than powered-off flash/HDDs, and provides an offline air gap immune to cyberattacks.
  • Data Retrieval Time Trade-off: While tape retrieval takes seconds to a few minutes (compared to milliseconds on RAID/NAS), archival records are accessed infrequently for audits or historical verification, making slightly slower retrieval an acceptable trade-off for massive capacity, longevity, and low cost.
Q-7

Critique: "Increasing CPU Clock Speed Alone Is the Best Way to Improve Performance"

Infographic: Why Clock Speed Alone Hits a Wall (The 4 Key Multipliers)

1. Cache Memory Size

Prevents CPU Starvation: RAM is ~100× slower than the CPU. Larger L1/L2/L3 caches keep data beside the cores so a fast clock isn't wasted waiting on RAM.

2. Word Length (32 vs 64-bit)

Data Width per Cycle: A 64-bit word processes twice as much data per clock tick as 32-bit and unlocks >4 GB RAM addressing.

3. Number of Cores

True Parallelism: Multiple cores run many threads simultaneously without hitting the extreme heat and power limits ("Power Wall") of 5+ GHz clocks.

4. Main Memory Capacity

Eliminates Disk Thrashing: Insufficient RAM forces the OS to swap pages to slow SSD/HDD storage, crippling speed regardless of CPU GHz.

Critique Statement: The claim that "increasing CPU clock speed alone is the best way to improve computer performance" is flawed and outdated. Clock speed (measured in GHz) only dictates how many raw cycles occur per second—not how much useful work is completed per cycle or how fast data reaches the processor. Furthermore, pushing clock speeds higher causes exponential heat dissipation and power consumption (the Power Wall).

  • Role of Cache Memory Size: Because DRAM is vastly slower than modern CPUs, a high-GHz processor without adequate L1/L2/L3 cache spends most of its cycles stalled waiting for data (the Memory Wall). Larger cache memory dramatically raises the cache hit rate, keeping execution pipelines fed.
  • Role of Word Length: Word length (e.g., 64-bit vs. 32-bit) defines how many bits the CPU registers, ALU, and data buses handle in a single operation. Doubling word length doubles numerical precision and data throughput per clock cycle while expanding directly addressable memory beyond 4 GB.
  • Role of Number of Cores: Modern operating systems, compilers, browsers, and multitasking workloads rely on parallel execution. A 4-core or 8-core CPU at 3.5 GHz completes multi-threaded tasks far faster and cooler than a single-core CPU pushed to 5.0 GHz.
  • Role of Main Memory (RAM) Capacity: If main memory capacity is too small for active programs, the operating system resorts to virtual memory paging/swapping on secondary storage (SSD/HDD), which is thousands of times slower than RAM and creates an immediate system bottleneck.
